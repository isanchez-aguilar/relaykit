# Changelog

All notable changes. Format based on [Keep a Changelog](https://keepachangelog.com/); versions follow [SemVer](https://semver.org/).

## [0.2.0] - Unreleased

### Changed

The technical names that still said Relaykit now say Relayrace. Nothing breaks on a machine configured under the old names: the new name is written, the old ones are still read (newest first), and nothing is moved or deleted for you unless it is noted below.

- Environment variables `RELAYKIT_*` are now `RELAYRACE_*` (`CONFIG`, `AGENT_DESK`, `NOTES`, `CONTRACT`, `PROVIDERS`, `QWEN_URL`, `QWEN_LOCK`, `ALLOW_FABLE`, `CLAUDE_EXE`, `AGY_EXE`, `CODEX_EXE`, `JULES_EXE`). Lookup order: `RELAYRACE_X`, then `RELAYKIT_X`, then the oldest `AI_KIT_X`; `doctor` still reports an old spelling in use.
- Config folder `relaykit` is now `relayrace` (`~/.config/relayrace/config.json`, Windows `%APPDATA%\relayrace\config.json`; `providers.json` sits next to it). Lookup order: `relayrace`, `relaykit`, `ai-kit`. Reading an old folder prints a one-line note telling you to move the file; Relayrace never moves or copies it.
- Install lock `.ai/relaykit.lock.json` is now `.ai/relayrace.lock.json`. The old file is read when the new one is absent; `init` and `init --update --apply` write the new file and remove the old one only after the new one is written.
- Global contract block markers `RELAYKIT_CONTRACT_START/END` are now `RELAYRACE_CONTRACT_START/END`, and the generated-file header now reads `GENERATED by relayrace sync — edit the source in the Relayrace repo ...`. Blocks and files carrying the old Relaykit (and the older ai-kit and Isaac) marks are still recognised as generated and are rewritten as ordinary updates on the next `sync`.
- The Antigravity rule file `~/.gemini/antigravity-cli/rules/relaykit-contract.md` is now `relayrace-contract.md`. The old file is retired by `sync` only when Relayrace generated it; a hand-written one is kept and reported as unresolved drift.
- Backup and temporary suffixes `.bak-relaykit`, `.bak-relaykit-<stamp>`, `.tmp-relaykit-` and `.restore-relaykit-` are now `.bak-relayrace`, `.bak-relayrace-<stamp>`, `.tmp-relayrace-` and `.restore-relayrace-`. Existing `.bak-relaykit*` files are left alone, and an existing `.bak-relaykit` counts as the first backup for the providers file and the Agent Desk config.
- Launcher and hook marks `Generated by Relaykit setup` and `# Generated by Relaykit ci-local` are now `Generated by Relayrace ...`; launchers, pre-push hooks and shell profile blocks written under the old marks are still recognised, so `setup`, `ci-local --install-hook` and `--remove-hook` keep working on existing installs. The Windows launcher folder `%LOCALAPPDATA%\Relaykit\bin` is unchanged because it is already on your PATH, and `bin/relaykit.mjs` still works for launchers and hooks that point at it.
- The providers editor's request header `X-Relaykit-Token` is now `X-Relayrace-Token` (internal to the page).
- The default Qwen lock folder stays `relaykit-qwen` on purpose, so older and newer copies of `qwen.mjs` installed in different repos keep sharing one lock.

## [0.1.0] - 2026-11-03

First public release.

### Added

- `relayrace doctor`, `init` (profiles `generic`, `web-app`, `notes`), `sync`, `update`, `providers`, `ci-local`, `relay`, `jules` and `qwen`.
- One-time setup scripts for Windows, macOS and Linux that install a launcher without administrator rights and ask before touching the user PATH.
- A providers file with plans, models, capabilities and priority order, a local editor (`providers ui`), and a relay that follows it per phase and never accepts a review from the implementer's model family.
- `init --update`: compares an installed repo with the kit and only replaces files that were never edited.
- `ci-local` and a pre-push hook: the repository's checks on this machine and, with Docker, in Linux containers.
- A neutral default contract.
- Published as `relayrace-ai` (command `relayrace`). The project was called Relaykit during development, and the technical names it already used are kept: `RELAYKIT_*` variables, the `relaykit` config folder, `.ai/relaykit.lock.json` and the generated-file markers.

### Security

- `init`, `init --update`, the relay and the Jules bridge never write through a symlink or junction that leaves the repository, create new files exclusively, replace files through unpredictable temporary names, and refuse a file that has a second hard link.
- `init` prints `deny` rules for secret files down to eight folders deep (and says when the scan stopped early), and the secret-file pattern is generic (`*secrets*.env`).
